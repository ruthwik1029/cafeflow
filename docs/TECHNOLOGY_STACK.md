# Technology stack

Verified development SDK: Flutter **3.47.9**, Dart **3.13.7**. The application uses
Material 3 and null-safe Dart on Windows, Android and Flutter Web.

| Direct dependency | Resolved version | Responsibility |
| --- | --- | --- |
| flutter | SDK 3.47.9 | Rendering, Material 3, platform integrations |
| flutter_riverpod | 3.5.0 | State and dependency injection |
| go_router | 18.1.4 | Declarative and target-isolated routing |
| supabase_flutter | 2.18.3 | Supabase Auth, PostgreSQL API, Realtime and Storage client |
| shared_preferences | 2.5.6 | Non-sensitive theme preference |
| flutter_test | SDK | Unit and widget tests |
| flutter_lints | 6.0.0 | Static code quality rules |

`pubspec.lock` records exact transitive dependencies and should be committed for
this application. Package constraints allow compatible updates; change the lockfile
only with analysis, tests and platform builds. Resolver notices about newer
incompatible transitive packages do not indicate a failed build.

Supabase is the only backend: hosted PostgreSQL, Auth, Realtime, Storage and RLS.
There is no Node.js application server, additional frontend framework, restaurant
template repository, custom microservice, or environment-loader dependency.

Inter and Space Grotesk are bundled variable font assets from Google Fonts under
their included SIL Open Font Licenses. No font CDN request is made at runtime.
Original icons are generated by an optional Pillow developer script. The app does
not require Python or Pillow at runtime.

The generated Android runner uses Flutter's SDK/NDK defaults, including the already
installed NDK **28.2.13676358**, and Java 17 language compatibility. Existing Android
SDK, NDK, Java, Gradle and Visual Studio installations are not reconfigured. Android
release verification uses the generated debug signing config; production signing
and store distribution are future release work. Windows uses the existing Visual
Studio Build Tools 2022 and CMake toolchain. Inno Setup packaging is not part of
this phase.

Flutter Web is intentionally the customer frontend per the product requirement.
Its canvas-rendered content has SEO constraints compared with conventional HTML;
metadata and semantics should be reviewed before public launch without introducing
another frontend stack.
